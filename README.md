# presheaf-curiosity

A lab notebook with code: **does a presheaf-flavoured view of graph data give any measurable advantage for MDL-based structure learning?**

The starting idea (from a conversation about "artificial curiosity" à la Schmidhuber): every presheaf is a colimit of representables (density), so a learner that sees its data as a presheaf could discover reusable sub-colimits ("macros"), pay for them once, and use the description-length gain as a learning-progress signal. This repository explores the *compression* half of that idea in small, honest experiments. The curiosity half (active data selection driven by the compression signal) is **not implemented or tested**.

## What this is, and what it is not

* It **is** a record of exploration: hypotheses, cheap experiments, negative results, corrections, and the code to rerun them.
* It is **not** a claim of beating RePair, gRePair, SUBDUE, gSpan or GraphMDL. The baselines labelled "RePair" or "gRePair-like" below are **our own re-implementations from the published descriptions** (no original code, partly without the original's optimisations). They are sanity baselines inside one cost model, not faithful reproductions.
* Almost all numbers are **development results**: learner and evaluation share one cost function, several worlds were generated by us, most real-data numbers are in-sample (same circuit, overlapping windows). A first small held-out test is described below.

Read `docs/lab-notebook.md` for the full story (it is long; the preface explains how to read it).

## The idea in four effects

| Effect | Categorical operation | Concretely |
|---|---|---|
| E1 Gluing | colimit / pushout | patterns glued from smaller patterns; instances pay only for boundary nodes |
| E2a Product | box product (closed monoidal) | grids as products of paths; closure gives unseen combinations |
| E2b Exponential B^A | internal hom | macros with holes (label holes, subgraph fillers, holes in holes) |
| E3 Fixpoint | initial algebra | a recursive lattice rule that extrapolates to larger instances |

## Claim / evidence / status

"In-sample" means evaluated on the data (or overlapping windows of the data) the model was fitted to. "Synthetic" means a world we generated to contain the structure sought. Section numbers refer to `docs/lab-notebook.md`.

| # | Claim | Evidence | Status |
|---|---|---|---|
| 1 | MDL selection explains most of the lead over gSpan/SUBDUE (run with our wrappers and limits) | several data sets and seeds (early results) | measured; not presheaf-specific |
| 2 | Gluing beats growing by one edge on hierarchical data | synthetic hierarchies 17/48/63 bits at depth 1/2/3; c6288 gate level 46-53 bits (3 seeds); Kinships 2.5-3.4, 16-atom molecules ~7 bits; streets and UMLS: no difference | measured; partly a search effect; in-sample on c6288 (1e, 4c) |

| 6 | Label holes (anti-unification) and a hybrid dictionary help | synthetic 13-92 bits; hybrid 4-10 bits better than either part; real data: hybrid -7.6 bits (c6288), -4.3 (streets) | synthetic strong, real small; label tables make the dictionary larger (4f, 4g) |

## Honest caveats

* Learner and evaluator share one cost function (home advantage); costs of bundle tables, runs and label tables are modelled, not produced by a real entropy coder.
* All "RePair"/"gRePair-like" numbers are from our own re-implementation (`src/repair.py`).
* Synthetic worlds are built to contain the sought structure; they show that the learner can find it, not that real data have it.
* Most real-data results are in-sample, on windows of a single regular circuit (c6288). Training/test windows overlap.
* Few seeds (3-10). Run-to-run variation from hash order is of the order of a few bits.
* The input bus, cell interiors and cell dictionaries are excluded in the quotient results.
* GraphMDL ran under time limits, SUBDUE and gSpan with restricted settings; they are not tuned opponents.
* Early scripts from the first days were lost in an environment reset; their results are summarised in the notebook but not reproducible from this repository.

## Quick start

```bash
python -m venv venv && . venv/bin/activate
pip install -r requirements.txt        # pynauty needs a recent setuptools
bash scripts/fetch_data.sh             # clones the public data sets into ./data (GitHub only)
python -m pytest tests                 # fast smoke tests
```

Paths are resolved in `src/paths.py`; override with `DATA_DIR` and `GEN_DIR` if your data live elsewhere. Run experiments from `src/` (they write to `../results`).

Data sets: ISCAS85/EPFL netlists (`ispras/hdl-benchmarks`, `lsils/benchmarks`), Spanish street networks (`amoraschi/spain-cities-geojson`). Kinships/UMLS (`src/kgdata/{kinships,umls}/train.txt`, tab-separated triples, e.g. from PyKEEN) and the RDKit solubility set (`src/mol/solubility.{train,test}.sdf`) are not bundled.

### Reproducing headline numbers

```bash
cd src
python genmul.py                        # own array multipliers mul4..mul32 (written to data/generated)
python quotient.py && python make_lattice_pos.py   # c6288 cell quotient: quotient.pkl, lattice_pos.pkl
python e32.py                           # 4k: lattice rule on the c6288 quotient
python e36.py                           # 4m: size test on own multipliers
python e43.py c6288 ; python e43.py mul # 4p: MDL-optimised Z² embedding (c6288 / own multipliers)
bash run31.sh 0 1 2 3 ; python agg31.py # 4j: depth-2 holes (seeds as arguments)
python heldout.py 0                     # held-out split of c6288 (glue/grow/RePair re-impl.)
python heldout_lattice.py 0             # held-out split: lattice rule learned on A, applied to B
```

Runs can take minutes to hours; pynauty-based steps are the slow ones. Some results depend on hash order (`PYTHONHASHSEED`); expect small deviations.

## Held-out test

A first held-out protocol is implemented but **has not produced results yet**: `src/heldout.py` splits the c6288 netlist into two disjoint halves by a seeded BFS (A: 2074 edges, B: 1758, 968 cut edges), learns on windows of A and evaluates on fresh windows of A and on windows of B; `src/heldout_lattice.py` learns cell formation and the lattice rule on A and applies them to B. The learning step on the half-circuit did not finish within an hour of CPU time on the two-core machine used here, so the only number so far is the empty-dictionary baseline (A: 363.5 bits/window, B: 413.5). Until these runs finish, **every result in the table above remains in-sample**. Contributions of finished runs are welcome as `results/heldout_*.json`.
